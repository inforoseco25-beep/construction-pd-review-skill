# construction-pd-review-skill

Skill для проверки томов проектной и рабочей документации (ПД/РД) объектов строительства РФ в стиле ГИП / руководителя группы контроля качества. Определяет тип и стадию тома, применяет профильную нормативную базу, классифицирует замечания по шкале RED / YELLOW / BLUE и формирует итоговый Excel-отчёт с замечаниями.

Skill предназначен для внутренней технической проверки состава и содержания томов ПД/РД. Он не заменяет экспертизу проектной документации, авторский надзор, юридическую или строительную экспертизу.

## Состав репозитория

- `SKILL.md` — основные инструкции, алгоритм проверки и обязательные правила запуска;
- `router/` — маршрутизация: определение применимого профиля тома;
- `references/` — нормативная база по типам томов (KR, AR, OOS, POS и др.) и общие требования (`common.md`);
- `rules/` — единые правила: стиль ГИП, классификация замечаний (`severity_rules.md`), формат Excel-вывода, цикл обучения;
- `CHANGELOG.md` — история изменений skill'а.

## Установка из GitHub

### Вариант 1. Через ZIP

1. На странице репозитория нажмите **Code → Download ZIP**.
2. Распакуйте архив.
3. Скопируйте папку целиком в `%USERPROFILE%\.agents\skills\construction-pd-review-skill` (Windows) или `~/.agents/skills/construction-pd-review-skill` (Mac/Linux).
4. Проверьте наличие файла `...\construction-pd-review-skill\SKILL.md`.
5. Перезапустите Claude/Codex, если skill не появился сразу.

### Вариант 2. Через Git

```bash
New-Item -ItemType Directory -Force -Path "$env:USERPROFILE\.agents\skills" | Out-Null
git clone https://github.com/inforoseco25-beep/construction-pd-review-skill.git "$env:USERPROFILE\.agents\skills\construction-pd-review-skill"
```

## Безопасность

- Не добавляйте в репозиторий папки `input`, `output`, реальные тома проектной документации, чертежи и документы конкретных объектов/заказчиков.
- Не сохраняйте токены, пароли, ключи API и персональные данные в файлах репозитория.
- Примеры (если добавляются) должны быть явно синтетическими, без привязки к реальным проектам.
- Перед публикацией проверяйте вкладку **Files changed** в Pull Request.
